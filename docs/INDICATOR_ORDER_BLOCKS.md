# Sonarlab · Order Blocks

Откройте пару → **Индикаторы** → **Sonarlab · Order Blocks** → **+**. Зоны отображаются на ценовом графике и продолжаются вправо. VMC можно использовать одновременно в его отдельной панели. Под графиком показаны количество активных зон и последний рассчитанный сигнал со временем UTC.

Кнопка **Настройки** у экземпляра или его название под графиком открывают вкладки **Аргументы**, **Стиль**, **Видимость**. Доступны исходная версия 1.0.2, Sensitivity (28), OB Mitigation Type (Close/Wick), Buy/Sell Signal, четыре цвета и прозрачность фона обеих сторон (85%). Применение сохраняет настройки отдельно для инструмента и экземпляра в `vector.indicators.v1`. Отмена, Escape и закрытие отбрасывают черновик; сброс меняет только черновик. Поддерживаются несколько экземпляров, порядок слоёв, скрытие, удаление и видимость на 15m/1h/4h/1d.

## Перенос исходника

Пользовательский Pine Script сохранён без изменений в `references/sonarlab-ob-original.pine`. Автор — © ClayeWeight, MPL-2.0. Вычислитель `src/indicators/order-blocks.ts` — перенос на TypeScript с сохранением атрибуции и условий MPL-2.0.

- ROC: `(open − open[4]) / open[4] × 100`. Порог — Sensitivity / 100, по умолчанию 0,28%. Пересечение вниз отрицательного порога создаёт медвежью зону, вверх положительного — бычью.
- Между текущим и предыдущим пересечением любого направления должно пройти **больше пяти** свечей. Первый переход лишь задаёт индекс. Даже пропущенный переход обновляет этот общий индекс.
- Поиск исходной свечи идёт от смещения 4 до 15 включительно: первая зелёная для медвежьей зоны, первая красная для бычьей. Границы — полный high/low. Если подходящей свечи нет, исходник использует текущую; это поведение сохранено.
- Close использует **одно закрытие предыдущей свечи** (`close[1]`), несмотря на комментарий про два закрытия в Pine. Wick использует текущий high/low. Медвежья зона удаляется строго выше top, бычья — строго ниже bottom. Равенство не удаляет зону.
- Сохраняется до 20 активных зон суммарно: при создании лишней удаляется самая старая. Удалённые зоны исчезают со всего графика. Такой предел соответствует назначению `max_boxes_count` и сборке старых объектов в [Pine](https://www.tradingview.com/pine-script-docs/v5/concepts/lines-and-boxes/).
- Условия сигналов буквально повторяют код: `high > bottom` для Sell и `low < top` для Buy. Дополнительной проверки входа снаружи нет. Сигнал возможен и на свече удаления, поскольку исходник проверяет ранее прочитанные границы после `box.delete`. Сначала проверяются новые медвежьи зоны, затем новые бычьи; сохраняется первый сигнал на свече по `alert.freq_once_per_bar`.

События являются расчётом по загруженной истории, а не внешними уведомлениями. При обновлении текущей свечи расчёт повторяется, поэтому последний сигнал может изменяться. Исторические события не отправляются как push или сообщения. Время события — время открытия свечи обнаружения; начало прямоугольника может быть раньше него. Свечи и сигналы незакрытого бара могут изменяться.

## Архитектура и проверка

`PairWorkspace → useOrderBlocks → computeOrderBlocks → MarketChart → OrderBlocksRenderer`. Hook использует те же свечи, что основной график, без дополнительных сетевых запросов. Renderer — [series primitive Lightweight Charts](https://tradingview.github.io/lightweight-charts/docs/5.0/plugins/series-primitives), привязанный к свечной серии и её шкале цен. Он следует масштабу и прокрутке, рисует зоны под свечами, не добавляет отдельную панель или временные точки и освобождается при закрытии графика.

`tests/order-blocks.test.ts` проверяет формулу ROC, переходы порога, общий интервал между ними, выбор исходной свечи, оба вида удаления и направления, сигналы и переключатели, предел 20 зон, повторный расчёт текущей свечи, повреждённые настройки и геометрию renderer.

Расчёт ограничен загруженной историей (обычно 400 свечей). Зоны, возникшие до её начала, неизвестны. Проверка с экспортом исходного индикатора из TradingView не выполнена; точное совпадение с его графиком не заявляется.
