# CoinGlass: визуальная настройка отбора

Базовая версия патча: `8fb643ac3a848ff5099cb2184358b6e86c33d032` (`main`).

## Использование

1. Добавьте CoinGlass к инструменту и откройте «Визуальная настройка» под графиком.
2. При первом запуске после обновления нажмите «Обновить данные CoinGlass». Старые результаты содержат только отобранные уровни; исходная карта для них через API недоступна. Старые линии остаются доступны до получения полного снимка.
3. После завершения первого сбора нажмите «Открыть собранную карту». При последующих обновлениях появится «Перейти на новый снимок». Во время настройки карта сама не заменяется.
4. Меняйте пороги и сторону. Пересчёт сохранённых данных выполняется без браузера CoinGlass, после паузы 180 мс. Пока он идёт, предыдущая карта приглушена; применение недоступно. Ошибка расчёта не выдаётся за пустую выборку.
5. Наведите на столбец или выберите цену в таблице. Показаны фактическая высота, выраженность, основание, расстояние от цены снимка и причины исключения. Переключатель «Все столбцы» позволяет посмотреть и обычные столбцы, не являющиеся пиками.
6. «Сравнить с сохранёнными параметрами» сравнивает два набора параметров на одном и том же снимке. Плюс означает новый уровень, минус — исчезающий. Это не сравнение двух дат рынка.
7. «Показать уровни на свечном графике» показывает свечи текущего инструмента и предполагаемые линии; исчезающие линии обозначены отдельно. Проекция снимка на исторические свечи не означает, что эти уровни были известны в прошлом.
8. «Применить» сохраняет параметры и закрепляет выбранный снимок для этого актива. «Отмена» и закрытие окна оставляют сохранённые параметры и линии без изменений. Явно запущенное обновление данных продолжает выполняться на сервере и при закрытии окна.

Карта отображается по числовой оси цены, с сегментами Binance / OKX / Bybit. Источник использует округлённые tooltip-значения. Ширина обзора и положение меняют только видимую область: максимум для порогов остаётся максимумом всей карты.

Вкладка «Снимок CoinGlass» показывает только снимок canvas карты (`chart-after.png`), если он был сохранён и не превышает 2 MB. Она не меняется при изменении параметров. Кумулятивные кривые доступны на исходном изображении, но не реконструируются на интерактивной карте: их числовые значения текущий сборщик не сохраняет.

## Параметры и алгоритм

- `minRelative`: интенсивность пика / максимум всей карты, диапазон 0–1.
- `minProminence`: (высота пика − основание) / максимум всей карты. Основание — большая из двух минимальных высот слева/справа, поиск прекращается у более высокого пика или края. Порог показан численно, фактическая выраженность выбранного столбца — оранжевым отрезком.
- `side`: выше/ниже цены снимка CoinGlass; текущая цена биржи в отборе не участвует.
- `limit`: общее число ближайших подходящих пиков, не отдельный лимит на каждую сторону. При равных расстояниях выше приоритет у более интенсивного пика, затем у меньшей цены.
- Плато представлено одним фактическим средним столбцом (для чётного числа — левым из двух средних). Маркер текущей цены исключается до поиска соседей. Края карты не считаются локальными максимумами.
- `hoverMs`: только задержка следующего сбора, не фильтр.
- Цвета, ширина и подписи меняют оформление; `staleHours` — только предупреждение об актуальности.
- Ноль выбранных уровней — успешный результат. Не подставляются обычные ближайшие столбцы.

## Архитектура и данные

`selection.py` — общий Decimal-расчёт для коллектора, CLI и API предпросмотра. Формулы не дублируются в TypeScript.

После успешной проверки полноты карты worker отдаёт снимок и результат. Сервис атомарно сохраняет полную карту в `/data/snapshots/<id>.json` (локальный запуск: `COINGLASS_DATA_DIR/snapshots`). Полные снимки не зависят от очистки последних 20 диагностических запусков. Версия схемы — 1, `snapshotId` — 32 шестнадцатеричных символа. В снимок входят только данные карты и необязательное изображение canvas; учётные данные и browser storage в API не попадают.

Снимки этой версии автоматически не удаляются: они могут быть закреплены пользователями. Рост каталога зависит от числа сборов и размеров изображений. Для будущей очистки нужна отдельная политика хранения с учётом закреплённых ссылок. `docker compose down -v` по-прежнему удаляет том вместе со снимками.

Новые внешние маршруты:

- `GET /api/coinglass/snapshot?symbol=BTCUSDT&snapshotId=<id>` — полная карта; без `snapshotId` возвращается последняя успешная.
- `POST /api/coinglass/preview` — `{symbol, snapshotId, params}`; возвращает выбранные уровни, все столбцы, причины и значения порогов. `params` содержит прежние пять полей расчёта.

Внутренние маршруты Python: `GET /snapshot?asset=BTC&snapshotId=<id>`, `POST /preview` с `asset` вместо `symbol`. Они используют существующую авторизацию `COINGLASS_TOKEN`. Node проверяет Origin, размер, параметры и формат идентификатора; Python проверяет соответствие актива и завершённость снимка. Предпросмотр не меняет очередь, статус задания или общий результат.

Выбор снимка хранится в `snapshotIds` настроек индикатора отдельно для каждого актива. Остальные параметры остаются общими согласно существующей модели проекта. Настройки сохраняются в браузере, серверного профиля пользователя проект не добавляет. Новый общий снимок другого пользователя не заменяет закреплённый. Для другого актива без закрепления используется его последний успешный снимок. Старые конфигурации без `snapshotIds` совместимы.

Новые зависимости не требуются: карта реализована SVG/React, свечи — существующим Lightweight Charts. Для Node standalone добавлена обработка тела POST нового маршрута. Маршруты приложения также доступны через существующий динамический Next API handler.

## Применение и сборка

Замените `<...>` своими значениями. Рабочее дерево должно быть чистым. Не продолжайте после ошибки команды.

```bash
cd "<PROJECT_DIR>"
git status --short
git switch main
git pull --ff-only <PRIMARY_REMOTE> main
git rev-parse HEAD
git apply --check "<PATCH_FILE>"
git apply "<PATCH_FILE>"
git diff --check
```

Проверки и автономная Node-сборка (Node 22.13+; Python 3 с зависимостями сервиса для его тестов):

```bash
npm ci
npm run typecheck
npm test
python -m unittest discover -s services/coinglass -p "test_*.py"
npm run build:standalone
npm run test:smoke
npm run start:standalone
```

При запуске без Docker Python-сервис запускается отдельно существующим способом; `.env` содержит `COINGLASS_SERVICE_URL` и при необходимости `COINGLASS_TOKEN`.

Docker: пересобрать **оба** сервиса, не только парсер. Существующие secrets, `.env` и том сохраняются:

```bash
docker compose -f compose.yaml -f compose.coinglass.yaml build
docker compose -f compose.yaml -f compose.coinglass.yaml up -d
docker compose -f compose.yaml -f compose.coinglass.yaml ps
docker compose -f compose.yaml -f compose.coinglass.yaml logs --tail=100 terminal coinglass
```

Проверка изменений, коммит и обычный push одной истории в обе `main`:

```bash
git diff --stat
git diff
git add -- app/globals.css services/coinglass/collector.py services/coinglass/selection.py services/coinglass/service.py services/coinglass/worker.py services/coinglass/test_collector.py services/coinglass/test_login_flow.py services/coinglass/test_selection_preview.py src/components/coinglass.tsx src/components/coinglass-map.tsx src/components/coinglass-candles.tsx src/components/coinglass-settings-dialog.tsx src/components/terminal.tsx src/domain/coinglass.ts src/hooks/use-coinglass.ts src/hooks/use-coinglass-preview.ts src/server/coinglass-service.ts standalone/server.ts tests/coinglass.test.ts docs/COINGLASS_VISUAL_SETTINGS.md docs/COINGLASS.md
git diff --cached
git commit -m "<COMMIT_MESSAGE>"
git push <GITLAB_REMOTE> main
git push <GITHUB_REMOTE> main
```

Имена remote проверьте через `git remote -v`. При необходимости добавьте отсутствующий remote: `git remote add <REMOTE_NAME> "<REPOSITORY_URL>"`. При расхождении историй сначала согласуйте их; не используйте force push. Защищённая main может требовать MR/PR.

## Проверки патча

Проверены: TypeScript typecheck, 47 Node-тестов, 87 Python-тестов, standalone production build и HTTP smoke. Дополнительно проверена связка собранного Node-сервера с Python API на контрольной карте из репозитория: полный снимок, те же пять уровней, пустая выборка, неизменность общего результата и отклонение чужого Origin. Тесты покрывают выраженность, плато, равные расстояния, стороны, лимит, исключение маркера цены, закреплённые снимки после перезапуска и проверки новых маршрутов.

Реальный вход и сбор с CoinGlass, Docker build и визуальная проверка в Chromium в среде подготовки не выполнялись. Chromium отсутствует, загрузка браузера завершилась сетевой ошибкой. После развёртывания проверьте интерфейс: изменение порогов без нового парсинга, сравнение, отмену, применение (включая 0 уровней), сохранение после перезагрузки страницы и явный переход на новый снимок.
