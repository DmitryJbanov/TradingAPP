# VMC Cipher B · VuManChu B Divergences

Источник: приложенный пользователем `vmc2.txt`, сохранён как `references/vmc2-original.pine` с исходными комментариями и атрибуцией. Это перенос формул на TypeScript; Pine runtime и платформа TradingView не требуются.

## Использование

Откройте пару → **Индикаторы** → **VMC Cipher B · VuManChu** → **+**. Под ценой появится отдельная панель. Разделитель между панелями можно перетаскивать; шкала времени общая, ценовая шкала осциллятора независимая. Можно добавить несколько экземпляров, менять их порядок, скрывать и удалять.

Кнопка **Настройки** у экземпляра или его название под графиком открывают окно:

- **Аргументы**: все группы входных параметров из Pine, включая источники цены, периоды, уровни, дивергенции, Sommi и MACD. Английские названия сохранены для сопоставления с оригиналом.
- **Стиль**: все 14 цветовых inputs оригинала, общая непрозрачность, толщина линий, уровни и малые точки пересечений.
- **Видимость**: отдельно 15m, 1h, 4h и 1d.

**Применить** сохраняет и пересчитывает; **Отмена**, Escape или закрытие окна отбрасывают черновик. **По умолчанию** восстанавливает исходные параметры в черновике. Настройки сохраняются по symbol и instance id в `vector.indicators.v1`; существующие записи без новых полей совместимы. Настройки локальны для браузера.

Кнопка **Обновить** повторно запрашивает свечи и дополнительные таймфреймы индикатора. Под графиком выводятся значения WT1, WT2, Fast WT, MFI, RSI, K, D и Schaff на свече под курсором, либо на последней свече. Прочерк означает отсутствие рассчитанного значения.

## Расчёт

| Компонент        | Формула / правило                                                                                                                                                             |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WaveTrend        | EMA источника за channel; EMA абсолютного отклонения за channel; CI = (source − ESA)/(0.015 × DE); WT1 = EMA(CI, average); WT2 = SMA(WT1, MA length)                          |
| Fast WT / «VWAP» | WT1 − WT2. Несмотря на название `VWAP` в оригинале, это не объёмно-взвешенная цена                                                                                            |
| RSI+MFI          | SMA(((close − open)/(high − low)) × multiplier, period) − Y offset. Объём в этой формуле не участвует                                                                         |
| RSI              | RSI источника через сглаживание Wilder RMA, с начальным SMA                                                                                                                   |
| Stoch RSI        | Опциональный log(source), RSI, стохастическая нормализация, SMA K, SMA D, опциональное среднее K/D                                                                            |
| Schaff           | EMA fast − EMA slow; две стохастические нормализации и рекурсивное сглаживание factor                                                                                         |
| Дивергенции      | Строгие фракталы из пяти баров; сравнение с предыдущим подходящим фракталом, его high/low и значением осциллятора                                                             |
| Gold             | Условия фактического блока `wtGoldBuy`: WT/RSI bullish divergence, предыдущий минимум относительно osLevel3, восстановление WT минимум на 5, RSI предыдущего WT-минимума < 30 |
| Sommi Flag       | MFI и WT текущего графика + Fast WT другого таймфрейма                                                                                                                        |
| Sommi Diamond    | Пересечение WT + направления двух Heikin Ashi свечей других таймфреймов                                                                                                       |
| MACD-цвета       | MACD 28/42, SMA signal 9 и MFI на выбранном таймфрейме                                                                                                                        |

EMA начинается с первого конечного значения, RMA — с первого полного среднего, SMA использует заданное число доступных наблюдений. `null` соответствует отсутствию значения: деление на ноль, недостаточная история и недоступные данные не заменяются нулевым сигналом. При high=low вклад MFI отсутствует. Нерассчитанные серии не рисуются.

У buy/sell, малых точек, Gold и дивергенций перенесены условия из раздела CALCULATE, а не их не всегда совпадающие описания в комментариях. Например, основной порог Gold использует RSI < 30. Флаг показа второго диапазона WT управляет его линиями, но не исключает его из `buySignalDiv`/`sellSignalDiv`: так написан оригинал.

## Время, подтверждение и перерисовка

Дивергенция становится известна на второй свече справа от экстремума. Линия и большая точка рисуются на экстремуме (`offset=-2`), однако `confirmedAt` и время события указывают бар обнаружения. Это не сигнал, доступный двумя свечами раньше. Время события — timestamp открытия бара обнаружения, а не wall-clock уведомление. Незакрытая свеча может менять значения и сигналы до закрытия.

В приложении можно выбрать один из двух режимов дополнительных таймфреймов:

- **Как в Pine (перерисовка)** — исходное поведение: WT/MACD сопоставляются по закрытию исторической свечи, а Heikin Ashi для Diamond с `lookahead_on` — с её начала. Поэтому Diamond на истории может использовать итог старшей свечи раньше момента его фактической доступности. На текущем баре используется доступное развивающееся значение.
- **Только закрытые свечи** — в MTF участвуют лишь свечи, закрытые к моменту оценки текущего бара. Исторические Diamond будут отличаться от исходного режима. Это не фиксирует основной незакрытый бар и не отменяет задержку подтверждения дивергенций.

При запросе младшего таймфрейма оригинальный HA-режим выбирает первый подбар, остальные исторические запросы — последний. Сопоставление учитывает время закрытия, не индекс массива. См. [официальное описание `security`, gaps и lookahead в Pine v4](https://www.tradingview.com/pine-script-docs/v4/essential/context-switching-the-security-function/).

## Интеграция и ограничения истории

MTF-параметры доступны для 15, 30, 60, 120, 240, 480, 720 минут и D. Эти интервалы обслуживаются текущими API-адаптерами. Произвольные Pine-разрешения, внешняя серия другого индикатора в качестве `input.source`, недельные и месячные свечи в этом патче не добавлены. Источники: open/high/low/close/hl2/hlc3/ohlc4.

`useVmc` объединяет одинаковые запросы всех активных экземпляров. Отключённые функции не вызывают MTF-запросы. При изменении инструмента, таймфрейма или параметров старый запрос отменяется, а его результат не принимается. Backend-кеш и совместное ожидание одинаковых запросов продолжают работать.

На каждый запрошенный таймфрейм доступно 400 последних свечей. Более короткий таймфрейм покрывает меньшую часть истории основного графика; там, где нет данных, MTF-сигналы отсутствуют и показано пояснение. В начале истории есть прогрев; при периодах до 500 некоторые значения на 400 свечах могут не появиться. Значения рекурсивных EMA/RMA и Heikin Ashi зависят от начала загруженной истории.

DEMO основного графика явно запрашивает DEMO дополнительных свечей. Для реального графика ответ MTF принимается только при совпадении `source` и `provider`. Ошибка или demo fallback дополнительного запроса не подмешиваются в реальный расчёт; базовые компоненты VMC продолжают работать. Доступ к интервалам Twelve Data зависит от ключа/тарифа; реальная интеграция с этим провайдером без ключа не проверена.

## Осознанные исправления и визуальные различия

1. В Pine перепутаны ограничения полей RSI Oversold/Overbought: их defaults 30/60 не входят в заданные min/max. Здесь оба поля допускают 0–100, defaults сохранены.
2. Оригинал вычисляет MACD-цвета, но не использует их в активных `plot`. Здесь **Show MACD Colors** действительно окрашивает WT1/WT2.
3. **Not apply OB/OS Limits on Hidden Divergences** показывает линии между неограниченными фракталами. В исходнике цвет вычисляется по ним, но `plot` местами остаётся ограничен другим набором фракталов; здесь переключатель действует последовательно.
4. Линии дивергенций явно соединяют сопоставленные экстремумы. Заливки, кружки, флажки и ромбы рисуются Canvas в custom series; это не пиксельная копия Pine `plot`/`plotchar`. Уровни показаны пунктиром. Исходные относительные прозрачности заливок сохранены в renderer; пользовательская непрозрачность применяется поверх них.

Побитовое совпадение с TradingView не заявлено: нужен экспорт OHLC и значений оригинала с того же инструмента, источника и начальной истории. Автотесты проверяют вручную рассчитанные векторы и временные инварианты; сверка с пользовательским экспортом TradingView ещё не выполнена.

## Код и расширение

| Файл                                     | Ответственность                                                                     |
| ---------------------------------------- | ----------------------------------------------------------------------------------- |
| `src/indicators/vmc-settings.ts`         | Типы, все 84 исходных inputs + режим MTF, defaults, ограничения и нормализация      |
| `src/indicators/pine-math.ts`            | SMA, EMA, RMA, RSI, стохастик, обработка отсутствующих значений                     |
| `src/indicators/vmc.ts`                  | Чистый `computeVmc(bars, params, context)` → points/events/warnings; MTF и фракталы |
| `src/indicators/vmc-renderer.ts`         | Custom series для отдельной панели, волны, заливки, линии и маркеры                 |
| `src/hooks/use-vmc.ts`                   | Дедупликация MTF-запросов, отмена и проверка происхождения данных                   |
| `src/components/vmc-settings-dialog.tsx` | Черновик настроек, вкладки, применение/отмена/сброс                                 |
| `src/components/chart.tsx`               | Жизненный цикл series, порядок и удаление панелей, общий crosshair                  |
| `tests/vmc.test.ts`                      | Численные примеры, временное выравнивание, фракталы, API и недоступные данные       |

`computeVmc` не обращается к сети, localStorage или chart API и не мутирует свечи. `context.now` измеряется в Unix-секундах, как Candle.time. `context.histories` содержит независимо загруженные OHLC других таймфреймов. `VmcResult.events` — вычисленные сигналы, а не отправленные alerts. Уведомления, ордера и бэктест не включены в патч. События Sommi вычисляются для включённых функций.

Панель реализована через [custom series API Lightweight Charts](https://tradingview.github.io/lightweight-charts/docs/plugins/custom_series), использует [общий механизм panes](https://tradingview.github.io/lightweight-charts/tutorials/how_to/panes). При обновлении данных сохраняется объект series и ручной масштаб; при удалении освобождаются series и её панель. В domain не хранятся объекты Canvas или библиотеки. Это позволяет позднее вынести вычисление в worker и добавить другие renderer-адаптеры.
