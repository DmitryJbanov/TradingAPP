# Pine Editor и мои скрипты

На странице инструмента кнопка **Pine Editor** открывает редактор под графиком. Кнопка **Индикаторы** открывает четыре раздела: «Индикаторы», «Стратегии», «Мои индикаторы», «Мои стратегии». Первые два содержат встроенные инструменты и примеры Pine; собственные скрипты появляются после сохранения.

## Работа со скриптом

1. Создайте индикатор или стратегию, вставьте Pine Script либо импортируйте `.pine`/`.txt`.
2. Задайте название. Сохраните кнопкой или `Ctrl+S`.
3. Нажмите «Сохранить и добавить на график» или `Ctrl+Enter`.
4. Управляйте видимостью кружком в списке над графиком. Нажатие на плашку пользовательского индикатора открывает его параметры и отображение; код открывается отдельной кнопкой **Открыть код** в карточке рабочего пространства. Удаление из рабочей области сохраняет скрипт в библиотеке; удаление из «Моих» удаляет его также с графика.

Редактор поддерживает подсветку синтаксиса, номера строк, отступ по Tab, экспорт `.pine`. Библиотека и черновик сохраняются локально в браузере (`vector.pine.library.v1`, `vector.pine.draft.v1`), без синхронизации между устройствами.

## Исполнение и совместимость

Исполнение Pine Script v5/v6 выполняет [PineTS 0.11.0](https://github.com/LuxAlgo/PineTS) в Web Worker. Скрипты v4 перед запуском автоматически переводятся в совместимый синтаксис v5: поддерживаются типичные миграции `study()` → `indicator()`, `security()` → `request.security()`, стандартные функции `ta.*`/`math.*`, типы `input.integer`/`input.resolution`, именованные аргументы `resolution` и стандартные цветовые константы. Старые вызовы `input(..., type=input.*)` переводятся в специализированные `input.*()`; числовые границы, исключающие заданное в исходнике значение по умолчанию, опускаются, чтобы сохранить это значение. Исходный текст скрипта и его версия при этом сохраняются без изменений. Это независимая реализация языка, а не движок TradingView; совместимость произвольного скрипта не гарантирована. Миграция не заменяет полный конвертер TradingView: конструкции v4, которым нужны другие изменения (например, `iff()` или `transp`), могут потребовать ручной правки. Расчёт использует OHLCV загруженных свечей текущей пары и таймфрейма, обновляется вместе с ними. `input.*` по умолчанию использует значения из исходника. В параметрах можно менять входные значения, видимость, цвет и стиль plot-рядов, маркеров, боксов, линий и подписей. Иконка скрипта выбирается из расширенного набора, её цвет задаётся отдельно; настройки сохраняются для экземпляра в рабочей области.

Общий Canvas-адаптер отображает Pine в панели, заданной overlay, и поддерживает force_overlay для вывода отдельных элементов на основной график. Доступны линии и линии с разрывами, ступени, ступени с ромбами, точки, крестики, гистограммы, столбцы, области относительно histbase и нулевой линии, горизонтальные уровни, заливки между рядами и градиентные заливки. Сохраняются цвета отдельных точек, прозрачность, offset, show_last, display.none и явный порядок слоёв explicit_plot_zorder. Для v4 поддерживается перенос transp у fill в color.new.

plotshape и plotchar отображаются в панели индикатора, включая абсолютные уровни, позиции над/под свечой, верх/низ панели, формы и текст. plotarrow отображает стрелки; plotcandle, plotbar и barcolor — OHLC-геометрию и окраску свечей. bgcolor рисует фон панели. Объекты box, line, label, polyline и linefill привязаны ко времени; поддерживаются продолжение линий с сохранением наклона, стили штриховки, многострочные подписи, кривые и заливки. Таблицы отображаются по позициям, с цветами, размерами ячеек, объединениями и подсказками. Подсказки подписей также доступны при наведении. trackprice выводит линию и значение на оси; scale.left/none и числовой формат учитываются при создании панели. В настройках скрипта доступны расширенные стили, видимость рядов, заливок и таблиц.

Это реализация визуализации поверх PineTS и Lightweight Charts, а не движок TradingView. Абсолютного совпадения всех произвольных скриптов, шрифтов и деталей графики не гарантирует. Визуальная проверка в браузере зависит от доступности локального приложения; геометрия также проверяется прямой отрисовкой Canvas. Для сложных скриптов остаётся необходимым сравнение с оригиналом TradingView. Ограничения PineTS в вычислении самого языка остаются. request.security() работает для текущего инструмента: D/W/M из дневных свечей, старшие внутридневные периоды из исходных, доступные младшие периоды — из отдельно загруженной истории.

Для `strategy()` PineTS рассчитывает сделки, капитал, чистую прибыль и максимальную просадку. На свечах показываются входы/выходы; под графиком — отчёт и последние 100 сделок. Это симуляция загруженной истории, без отправки ордеров. Результаты могут отличаться от TradingView из-за реализации движка и источника/объёма истории.

Исполнение ограничено 5 минутами на скрипт и 10 000 итерациями циклов; размер исходника — 100 000 символов. Ошибки показываются с названием скрипта. Расчёт в worker не блокирует интерфейс; доступ runtime к сети отключён.

Обновления цены не прерывают текущий расчёт: после его завершения выполняется расчёт последнего полученного снимка свечей. Смена пары, таймфрейма или кода отменяет старую задачу. Координаты объектов привязаны ко времени свечей, включая продолжение за правый край истории; обновление окна свечей не сдвигает готовую разметку. Кэшированные и свежие свечи одного провайдера допускается использовать совместно, демоданные с рыночными не смешиваются.

### Вложенные MTF-запросы VMC

Для `security()` в v4 также загружаются дневные свечи и, при необходимости, младший внутридневной период из параметров скрипта. Старшие внутридневные периоды (например, 12 часов) агрегируются из свечей источника. `heikinashi()` преобразуется в `ticker.heikinashi()`; производные OHLC рассчитываются после агрегации. Свечи других инструментов не запрашиваются. В PineTS 0.11 усечённые тела MTF-запросов используются для обычных вызовов. Для вызовов внутри пользовательских функций применяется полный вторичный скрипт, сохраняющий историю параметров. Готовая полная история вторичного контекста повторно используется для других выражений того же инструмента, модификатора и периода, если нужный ряд присутствует; запросы с явно заданным calc_bars_count остаются независимыми. Младшая история ограничена 12000 свечами; вне её диапазона значения младшего периода отсутствуют.

Worker сохраняется между обновлениями свечей, а скомпилированный индикатор повторно используется при неизменном коде и входных параметрах. Расчётные контексты для новых свечей создаются заново, поэтому результат не берётся из устаревшего снимка. При смене инструмента, таймфрейма, параметров или списка скриптов workers освобождаются.
